# 기술 결정 기록

## D-001: 신규 React·TypeScript·Vite 정적 PWA

- 결정: 서버 렌더링 없이 React UI와 Vite 정적 빌드를 사용한다.
- 이유: 기획서의 기술 기준과 오프라인·동일 출처 정적 호스팅 요구에 직접 맞고 런타임 서버가 필요 없다.
- 검토 대안: Next 계열 앱 셸, 바닐라 TypeScript.
- 장단점: 개발·테스트가 단순하고 설치 크기가 작다. 라우팅·서버 기능은 제공하지 않지만 현재 범위에는 필요 없다.
- 변경 조건: 계정, 공유 링크, 서버 동기화가 별도 승인될 때 서버 아키텍처를 다시 검토한다.
- 관련 기획: 16장, 19.1절, 25장.

## D-002: 외부 상태관리·Canvas 라이브러리 없음

- 결정: React 상태는 UI 상태만, 드로잉 세션은 명령형 TypeScript 클래스로 관리한다.
- 이유: 포인터 프레임마다 React 전체 렌더를 일으키지 않고 입력·렌더·저장 책임을 분리한다.
- 검토 대안: 전역 상태관리 라이브러리, Fabric/Konva 계열 캔버스 라이브러리.
- 장단점: 번들과 제스처 간섭이 작고 로직 테스트가 쉽다. 세션 생명주기와 정리를 직접 관리해야 한다.
- 변경 조건: 편집 가능한 객체, 다수 레이어, 협업 상태가 도입될 때.
- 관련 기획: 18.2절, 19.2절, 19.4절.

## D-003: 스트로크 저널 기반 히스토리와 결정적 재생

- 결정: 현재 슬라이스에서는 스트로크 명령을 최대 50개 저장하고 확정 표면을 재생해 undo/redo한다.
- 이유: 전체 캔버스 ImageData 복사는 1080×1920에서 단계당 약 8MB라 메모리 예산을 빠르게 초과한다.
- 검토 대안: 단계별 전체 래스터 스냅샷, 타일 diff.
- 장단점: 메모리 사용이 예측 가능하고 저장 복구와 같은 모델을 쓴다. 긴 히스토리의 재생 비용이 증가한다.
- 변경 조건: 50단계 재생이 실기기에서 상호작용 지연을 유발하면 주기적 래스터 체크포인트를 추가한다.
- 관련 기획: 8.4절, 13.1절, 20.2절, AC-10.

## D-004: IndexedDB 직접 사용과 두 단계 리비전 커밋

- 결정: 래퍼 없이 네이티브 IndexedDB를 작은 Promise 도우미 뒤에서 사용한다. 새 리비전을 `pending`으로 저장한 후 동일 리비전을 `complete`로 바꾸고 프로젝트 활성 포인터를 교체한다.
- 이유: 외부 의존성 없이 트랜잭션과 오류 원인을 명시적으로 다루고 이전 정상 리비전을 보존할 수 있다.
- 검토 대안: idb/Dexie, 단일 레코드 덮어쓰기, localStorage.
- 장단점: 번들이 작고 마이그레이션이 명시적이다. IndexedDB 보일러플레이트를 직접 유지한다.
- 변경 조건: 다수 프로젝트·자산·마이그레이션이 늘어 래퍼의 이점이 번들 비용보다 커질 때.
- 관련 기획: 13장, 19.4절, 20.3절, AC-15~AC-18.

## D-005: 검증용 기본값과 모바일 정사각형 새 작업

- 결정: 신규 기본 캔버스는 1080×1080 흰색으로 하고 기존 세로 저장본의 크기는 유지한다. 히스토리 50, DPR 상한 2, 확대 5%~800%, 두 손가락 탭 220ms/12px, 핀치 거리 변화 3%, 상태 안정화 50ms를 사용한다.
- 이유: 모바일 화면에서 세로 작업의 과도한 축소를 줄여 실제 그리기 면적을 확보하되 기존 사용자 작업을 자르거나 변환하지 않기 위해서다.
- 검토 대안: 기기별 자동 튜닝, 사용자 임계값 설정.
- 장단점: 검증 가능하고 일관적이다. 일부 기기에서 최적이 아닐 수 있다.
- 변경 조건: iOS/Android 실기기 오탐·지연 측정이 기준을 벗어날 때 상수만 조정한다.
- 관련 기획: 9장, 10.2절, 12장, 28.1절.

## D-006: 두 번째 마일스톤의 퀵 브러시 4종

- 결정: 펜, 연필, 반투명 마커, 실제 알파 지우개를 제공하고 각 도구의 굵기를 기억한다. 색상은 빠른 팔레트 5색과 시스템 색상 선택기를 제공한다.
- 이유: 핵심 수직 슬라이스 검증 후 제기된 실제 사용성 피드백에 따라, 모바일에서 한 번 탭으로 자주 쓰는 도구를 바꿀 수 있어야 한다.
- 검토 대안: 브러시 선택 모달, 7개 브러시 동시 구현, 지우개를 흰색 펜으로 구현.
- 장단점: 퀵 전환과 히스토리 재생이 단순하며 지우개가 배경색에 종속되지 않는다. 질감 브러시와 도구별 고급 설정은 아직 없다.
- 변경 조건: 질감·스탬프 브러시를 추가할 때 렌더러를 브러시 전략 모듈로 분리한다.
- 관련 기획: 첨부 작업 지시 5~7장, 종합 기획 22.1절과 27장.

## D-007: PNG만 내보내고 Web Share 실패 시 다운로드

- 결정: 메모리의 최신 확정 상태를 원본 좌표로 별도 렌더해 PNG Blob을 만든다. 파일 공유가 가능할 때만 공유하고, 사용자 취소 외 실패와 미지원은 다운로드한다.
- 이유: 현재 슬라이스 필수 범위이고 확대·이동과 출력 분리를 검증한다.
- 검토 대안: 표시 캔버스 캡처, JPEG 동시 제공.
- 장단점: 결과 크기와 품질이 결정적이다. JPEG와 대형 출력 축소 UX는 후속 범위다.
- 변경 조건: 다음 MVP 마일스톤에서 배경·JPEG 품질 설정을 추가할 때.
- 관련 기획: 15장, AC-19~AC-21.

## D-008: 수동 서비스 워커와 사용자 승인 업데이트

- 결정: 빌드 결과의 동일 출처 셸 자산을 서비스 워커가 캐시하고, 새 워커는 대기한다. 앱은 저장 성공 뒤 사용자 승인으로 `skipWaiting`을 보낸다.
- 이유: 편집 중 강제 새로고침과 데이터 스키마 충돌을 막고 필수 CDN을 없앤다.
- 검토 대안: Vite PWA 플러그인, 즉시 활성화.
- 장단점: 동작이 투명하고 의존성이 없다. 빌드 해시 프리캐시 자동 생성은 단순화되어 있다.
- 변경 조건: 자산 수와 라우트가 늘어 수동 목록 유지가 위험해질 때 PWA 플러그인을 재평가한다.
- 관련 기획: 16장, AC-22, AC-23.

## D-009: 배경 이미지는 리비전 Blob과 합성 상태로 분리

- 결정: 가져온 이미지는 최대 긴 변 4096px·16MP로 정규화한 Blob으로 저장하고, 프로젝트 스냅숏에는 맞춤/채우기·90도 회전 상태만 기록한다. 화면·내보내기 시 배경을 먼저 합성한다.
- 이유: 대형 data URL을 JSON 스트로크 데이터에 반복 복제하지 않으면서 재실행 복구와 원본 파일 왕복을 제공하기 위해서다.
- 효과: 지우개는 투명 드로잉 레이어만 지워 배경 사진을 드러내며 PNG/JPEG 모두 동일한 합성 결과를 낸다.
- 관련 기획: 6.5장, 7.7장, 13장, 15장.

## D-010: 인터넷 이미지는 URL 직접 요청과 클립보드 대체 경로 병행

- 결정: 사용자가 입력한 HTTPS 이미지 URL을 CORS가 허용할 때 직접 가져온다. 검색 버튼은 이미지 검색 결과를 새 탭으로 열고, 사용자가 복사한 이미지는 클립보드/붙여넣기로 받는다.
- 이유: 정적 PWA가 타 사이트의 CORS 정책을 우회하는 것은 불가능하다. 실패를 숨기지 않고 로컬 선택과 붙여넣기를 항상 제공한다.
- 모바일: Android는 Web Share Target으로 공유된 이미지도 받으며 iOS는 파일 선택·사진 보관함·클립보드 경로를 사용한다.
- 관련 기획: 이미지 가져오기, 모바일 공유·PWA 요구사항.

## D-011: 프로젝트별 리비전과 제한 레이어

- 결정: 각 새 그림은 UUID 프로젝트가 되고 최근 작업 목록에서 열기·복제·소프트 삭제한다. 드로잉 레이어는 최대 8개이며 표시·농도·순서를 렌더러가 해석한다.
- 이유: 모바일에서 복잡한 데스크톱 레이어 모델을 그대로 노출하지 않고도 초안 분리와 배경 사진 위 작업을 지원하기 위해서다.
- 제한: 레이어 추가·복제·삭제 자체의 명령 단위 undo, 이름 변경, 병합은 후속 범위다. 스트로크 undo/redo는 레이어별로 정상 동작한다.
- 관련 기획: P1 작업 목록·제한 레이어·프로젝트 파일 왕복.

## D-012: 선택 가능한 경량 브러시 엔진과 벡터 명령

- 결정: 스트로크 포인트에 압력·기울기를 선택적으로 저장하고, 도구별 보정·흐름·경도·간격 설정을 스트로크 명령에 함께 기록한다. 페인트통과 도형도 동일한 히스토리 명령으로 재생한다.
- 이유: 기존 프로젝트 파일과 스트로크 undo 구조를 유지하면서 모바일 입력 표현력과 결정적 저장·복구를 확장하기 위해서다.
- 레이어: 각 레이어를 독립 투명 표면에 렌더한 뒤 합성해 지우개와 페인트통이 다른 레이어를 손상하지 않게 한다.
- 호환성: 새 필드는 선택적이며 기존 스키마 v1 스트로크는 기본값으로 그대로 재생한다.

## D-013: 버전형 도구 환경설정과 시작 완료 후 저장

- 결정: 마지막 도구·색상, 도구별 굵기·농도·고급 설정, 최근/즐겨찾기 색상을 `localStorage`의 `fingertip-tool-settings-v2`에 저장한다. 기존 `v1`을 자동으로 읽고, 이전 캐시나 롤백 앱을 위해 `v1` 키도 최신 값으로 함께 기록한다.
- 이유: 도구 설정은 작은 기기별 UI 환경설정이라 프로젝트 리비전과 분리하는 편이 즉시 복구와 앱 업데이트 호환에 적합하다. 컨트롤러 초기화 전에는 쓰지 않아 기본 펜 값이 기존 사용자 설정을 덮어쓰지 않게 한다.
- 모바일: 새 그림, 새로고침, 홈 화면 PWA 업데이트 뒤에도 같은 출처의 설정이 유지된다. 브라우저 사이트 데이터 삭제, 비공개 모드 종료, 다른 기기에는 자동 전송되지 않는다.
- 변경 조건: 계정 또는 기기간 동기화가 승인되면 서버 동기화와 충돌 해결 정책을 별도로 설계한다.

## D-014: 자동 맞춤 보기와 모바일 책갈피 도구 메뉴

- 결정: 문서 해상도는 1080×1080으로 유지하고 표시 배율만 현재 작업 영역에 자동 맞춘다. 사용자가 핀치·휠·단축키로 보기를 조절하면 그 중심을 유지하고, 맞춤을 선택하거나 기기별 새 로드가 발생하면 자동 맞춤으로 돌아간다.
- 확대 UI: 평상시에는 숨기고 실제 사용자 확대·축소 직후 1.6초와 키보드 포커스 중에만 표시한다.
- 모바일: 너비 720px 이하 또는 높이 650px 이하에서는 도구 선택 후 유휴 상태에 메뉴를 접는다. 그리는 중에는 접힘을 미루고, 선택 도구를 표시하는 책갈피로 다시 연다.
- 이유: 작은 화면에서 캔버스 면적을 우선하면서도 도구 발견성과 키보드 접근성을 유지하기 위해서다.

## D-015: 프로젝트에 포함되는 다국어 윤곽선 단어 안내

- 결정: 영어·한글·일본어·중국어의 내장 단어 목록에서 언어와 단어를 무작위로 선택한다. 언어별 시스템 글꼴 묶음으로 캔버스 폭 88%·높이 66% 안에 맞춘 뒤 채우기 없이 반투명 윤곽선만 렌더링한다.
- 저장: 선택한 언어와 단어를 기존 프로젝트 스키마의 선택 필드로 저장해 이전 프로젝트 호환성을 유지한다. 화면·체크포인트·원본 파일·PNG/JPEG에 같은 윤곽선을 합성한다.
- 이유: 네트워크 글꼴 의존 없이 iOS·Android·PC에서 오프라인으로 즉시 따라 쓰고, 사용자 획은 기존 드로잉 레이어에 독립적으로 남길 수 있다.
